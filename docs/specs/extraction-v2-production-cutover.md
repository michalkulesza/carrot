# Extraction v2 production cutover

Status: implementation wired; acceptance verification remains. Static Python compilation, web production build, mobile TypeScript check, and diff checks pass. The frozen-capture integration cases and production-like smoke imports remain pending. This is a permanent replacement of the legacy URL/text extraction path, not a dual-run or feature-flag rollout. TikTok and Facebook review fixtures will be added separately after this work; their absence does not block implementation.

## Outcome and scope

New website, Instagram, TikTok, and pasted-text imports use extraction v2 for source facts. Facebook remains a follow-up because the current live scraper has no Facebook acquisition path; a Facebook URL must receive a typed unsupported-source result until one exists, rather than being mistaken for an ordinary recipe page. The existing Gemini enrichment remains model-based. Image imports keep the necessary Gemini vision source-reading step because v2 has no image input; they share the revised enrichment, outcome, and persistence contracts where applicable. Existing saved recipes are not re-extracted.

There is no runtime route back to legacy URL/text extraction, no legacy retry after a v2 failure, and no duplicate production pipeline. Remove dead legacy functions, files, configuration, tests, and documentation references after their last callers are migrated. Preserve code still used by image imports, backfills, or other active flows.

Production imports must distinguish complete, saved-incomplete, and failed results. A saved partial recipe retains its source URL and any grounded ingredients or instructions. Every canonical fact remains attributable to source evidence. Enrichment may derive variants, categories, tags, and estimates for empty fields but cannot change canonical recipe facts or invent missing amounts, instructions, or step temperatures/times. Every displayed nutrition and total-time value identifies whether it came from the source, AI, or a user edit.

## Existing boundaries

- `services/api/src/api/services/extraction_v2/orchestrator.py` already sequences social text, linked pages, and audio, verifies comments, gates languages, and returns `CompleteOutcome`, `IncompleteOutcome`, or `FailedOutcome`. It has no production caller.
- `extraction_v2/extractor.py`, `gemini_selection.py`, `language.py`, and `adapters.py` provide the real v2 extractor, optional grounded social-text selection, language detection, and Gemini audio evidence adapter. Assemble these explicitly for production; do not leave the review runner as the only composition root.
- `services/api/src/api/services/pipeline.py` is the live legacy URL/text/image path. `import_worker.py` consumes its `ImportResult`, then persists a `Recipe`. The enqueue route already uses an idempotency key, and the worker locks a job before saving. Preserve those safeguards.
- `gemini.py` has a source-only schema, model enrichment, step-to-ingredient matching, unit variants, and conditional allergen analysis. Its current enrichment schema requires numeric macros and may estimate total time; revise this contract for v2's unknown/source/estimated distinctions.
- `Recipe.components` is JSON, while recipes and import jobs lack persisted v2 issues, evidence, and failure-stage fields. `RecipeSaveRequest`, `RecipeOut`, `ImportJobOut`, shared TypeScript types, and web/mobile recipe detail views need coordinated changes. Schema upgrades currently live in `main.py` startup SQL and must also work for the worker startup path.
- `docs/specs/rendered-html-imports.md` owns headless rendering. Integrate with its bounded renderer when available. Until then, use a bounded safe HTML fetch; renderer failure may fall back to raw HTML, but extraction itself must never fall back to the legacy pipeline.

## Decisions for implementation

1. **Source facts stay authoritative.** Keep v2 ingredient and step strings exactly, in order and grouped by component. Do not run Gemini source extraction again over v2 output. The handoff maps each ingredient's full source string to `SourceIngredient.name` with `qty/unit = null` until the separately reviewed amount parser is available. This preserves current display and shopping-list behavior without a lossy split. Preserve source title, stated servings, time, nutrition, component headings, linked ingredient URLs, and their references. Do not invent a title: if persistence requires a label, use a localized/display fallback separate from the canonical title.
2. **Enrichment stays model-based and fills gaps field by field.** Reuse the existing Gemini enrichment and conditional allergen pass, but give them v2 facts through a dedicated adapter. Validate one-to-one component/ingredient/step alignment and keep canonical fields out of model-writable output. For `total_time_minutes`, `kcal_per_serving`, `protein_per_serving`, `fat_per_serving`, and `carbs_per_serving`, the server first accepts valid source-provided values individually. Ask Gemini to estimate only fields still empty; a source calorie value does not prevent estimating missing carbohydrates, and Gemini cannot rewrite that calorie value. Missing total time may be a separately labelled AI estimate, never an invented time inside a source step. Unknown component composition or missing quantities may leave individual nutrition fields unknown instead of forcing zeroes or a confident total. Generate a brief overview only from supported steps; omit it for instruction-free recipes. Keep variant arrays aligned, falling back to source wording for an individual unsafe conversion.
3. **URL acquisition matches the v2 envelope.** Direct HTML imports supply raw/final HTML and final URL. Social imports supply the raw ScrapeCreators-shaped response, verified creator comments with authorship evidence, caption, linked URLs, and media URL or transcript. Extend acquisition only through supported provider endpoints; add a closed `UNSUPPORTED_SOURCE` failure code for an unhandled social platform and map it through the job/UI contract. Do not synthesize creator authorship from a username string alone. Transcribe only when text and eligible linked pages remain incomplete; a complete text result makes no audio call.
4. **Pasted text uses v2 directly.** Wrap the pasted content as one normalized text evidence source and invoke v2 language detection plus `extract_text`, then use the same completion and enrichment path. A new source kind/entry point may be added to the v2 contracts; do not fake a social post. Image import retains Gemini vision for image reading, then passes its source facts through the common persistence and UI outcome contract where possible.
5. **No hidden recovery to legacy.** A v2 content failure remains a typed failed import; a transient operational failure uses bounded worker retries. A partial v2 result is saved once with its issue code. Disable legacy cache reuse for v2 unless the cache key includes extractor version and source-input identity; do not serve old extracted recipes as v2 results.

## Work packages

### 1. Production acquisition and dependency assembly

- Add an injectable production composition root for `ExtractionOrchestrator`: `RecipeEvidenceExtractor`, `LinguaLanguageDetector`, `GeminiTextSelectionProvider` for social text, safe linked-page provider, transcription provider, and `GeminiAudioEvidenceExtractor` with usage tracking. Match the review runner's social selection policy. Give every call bounded time/input limits.
- Build `HtmlPayload` and `SocialPayload` from live acquisition with the same versioned schema as frozen fixtures. Capture raw scraper response before parsing; extend the scraper client to return raw data and author-verifiable comments. Collect explicit full-recipe URLs from both the post description and verified creator-authored comments/replies, including callouts such as "go here for the recipe"; resolve their redirects and extract the linked HTML before audio fallback. Never follow a viewer-authored URL or treat a linked component recipe as the post's full recipe. Include a capture status/error when a field is unavailable. Keep secrets, raw captions, HTML, and transcripts out of ordinary logs and Sentry.
- Validate URL scheme, hostname resolution, redirect destinations, and final destination against private/local networks before network access. Bound response bytes, redirects, time, and social/linked page count. Reuse the rendered HTML service when that plan is implemented; make its operational raw-fetch fallback observable.
- Add a direct pasted-text adapter and verify supported/unsupported language behavior.

### 2. Evidence-to-enrichment handoff

- Add a named adapter from `CompleteOutcome`/`IncompleteOutcome` to immutable source facts plus safe enrichment input. Map v2 component names and raw ingredient/step strings without translation or reparsing. Treat source `yield_servings`, `total_time_minutes`, and nutrition as evidence-backed values; validate parsed numeric fields against their original quotes.
- Revise `RecipeEnrichment`/`RecipeExtraction` and assembly to allow nullable nutrition/time fields, incomplete-nutrition and uncertain-allergen state, and an overview grounded in steps. Build a field-level `missing_fields` request for the five values above; include present source values only as read-only context. The model response may contain only requested estimates, and the server assembles final values from source facts first, then accepted estimates for missing fields. Reject or ignore any model attempt to return a non-requested value. Do not require an estimate when the evidence is insufficient. Keep existing model-based unit variants, shopping values/categories, tags, step matching, and allergen pass where applicable; reject/repair malformed derived arrays without replacing source text.
- Persist field-level provenance for those five values as `source | ai | user | unknown` alongside the numeric value. `source` has a resolvable evidence reference; `ai` is a model estimate; `user` means the person supplied or changed the displayed value; `unknown` means no value or an older recipe whose origin cannot be established. A full recipe edit must preserve provenance for unchanged fields, change only edited values to `user`, and set a cleared field to `unknown`. Keep the original source evidence even after a user edit.
- Make enrichment failure policy explicit: an operational model error retries the job within existing limits; a permanently invalid enrichment response produces a typed failure rather than saving altered facts. A recipe with no instructions has no overview or guided cooking flow.

### 3. Persist outcomes and make retries safe

- Add durable recipe issue codes and item-level source references/links. Store bounded, versioned evidence and trace material separately from user-facing recipe fields, with access limited to authorized recipe members. Define retention and deletion with the recipe; avoid duplicating full private page/transcript content in logs or events. Persist each nutrition/time value and its provenance independently, including mixed source/AI recipes.
- Extend import-job failure code and failed-stage storage to map the closed v2 `FailureReason` enum. Keep content failures terminal, retry only transient acquisition/model failures, and map unknown codes to a safe operational fallback. Include sanitized source URL, stage, reason, and outcome in diagnostics.
- Save complete and incomplete outcomes in one transaction with the import job status and recipe link. Guard requeued/repeated jobs against duplicate recipes; preserve the existing enqueue idempotency behavior. Do not create an empty recipe when both ingredients and instructions are absent.
- Add an authorized, idempotent endpoint to dismiss exactly one persisted missing-content issue. Recipe edits may resolve an issue when the missing content is supplied; dismissal alone does not create content or enable cooking mode.
- Apply additive schema upgrades in both API and worker startup paths before the new worker reads/writes the fields. Existing recipes default to no v2 issues and unknown provenance rather than being rewritten.

### 4. Web/mobile contract and UI

- Update API outputs, `packages/shared/src/types.ts`, and clients for complete/incomplete/failed outcomes, closed failure reasons, issue codes, per-field nutrition/time provenance, linked component URLs, and source inspection.
- Show saved partial recipes with a localized issue banner, source action, and safe ingredient/step content. Preserve linked component ingredients as clickable links with an explicit action to import the linked recipe separately; never auto-import it. Disable cook mode when steps are absent; explain why. Label each AI-generated nutrition/time value individually in web and mobile detail views; show source, user-edited, and unknown values accurately, including a recipe with source calories and AI-estimated carbohydrates. Do not show a fabricated overview, complete nutrition total, or “no allergens” when the source leaves them unknown. Dismiss only the selected issue and reconcile rapid repeated taps against the server response.
- Map content failures to source inspection/alternate input and transient operational failures to retry. Ensure a failed import is not displayed as a saved partial recipe. Add strings to en, pl, de, fr, and es; check mobile and web narrow layouts and existing recipe behavior.

### 5. Permanent cutover and cleanup

- Route URL and pasted-text jobs through the new v2 path. Keep image vision only for its distinct modality. Remove the legacy URL/text branch, JSON-LD-to-Gemini preparation, old social fallback sequencing, any now-unused HTML stripping/fetch helpers, legacy-only response adapters, cache entries/keys, and obsolete tests. Search every caller first, including `services/api/scripts/reimport_recipes.py`, manual import routes, backfills, and tools; migrate active callers or keep a shared helper only when still used. Do not delete frozen review fixtures or regression expectations.
- Remove dead configuration, comments, docs, and UI states that imply a legacy extractor switch. Update the review tooling if imports moved. Keep the cutover plan and backlog current; move this plan into `docs/specs/completed/` only when implementation and verification are finished. Include the plan in any eventual user-approved commit.

## Acceptance and verification

- Frozen HTML and Instagram captures pass through the **production** composition root and return the same source facts, evidence references, outcome, and fallback decisions as the review path. Add focused integration cases for caption-only success, verified creator comments, linked HTML, transcript fallback, partial saved result, empty failure, unsupported/undetermined language, and renderer/raw-fetch behavior. TikTok/Facebook fixture expansion follows separately and is not required to write or implement this cutover.
- Test that a complete caption performs no linked-page, transcription, or audio-model call; a partial caption follows a full-recipe URL from either the caption or a verified creator comment before audio; viewer comments and their links never contribute facts; repeated/concurrent jobs create one recipe; one issue dismissal cannot remove another; and a failed enrichment never overwrites canonical facts. Test field-level enrichment with source calories but missing carbohydrates, source time with missing macros, all source fields present, all fields missing, insufficient evidence, and a model response that tries to replace a source value. Verify unchanged edits preserve provenance and changed/cleared values update only their own provenance.
- Exercise the database upgrade, API contracts, web and mobile partial/error states, all five locales, source links, cook-mode guard, and null/estimated nutrition. Run focused API tests, the full API suite, web/mobile typecheck/lint/build, and `git diff --check`; record any environment-limited checks honestly.
- Inspect the final diff and perform a production-like smoke import of a website and a social post, including one incomplete case. Check source evidence, issue display, Sentry-safe diagnostics, worker retries, and duplicate handling. Release only after the user's manual review and explicit approval of the v2 results; the missing TikTok/Facebook fixture set does not itself block that review.
- After deployment, monitor import success/partial/failure by source and reason, model cost/latency, and missing critical fields without sending recipe content to telemetry. On a severe regression, stop new imports or fix forward; there is no runtime legacy extractor fallback.

## Implementation workflow

Another model can execute the five work packages as bounded tasks in a branch/worktree. For each task, save progress, run the focused checks, inspect the diff and relevant tests/CI, and repair failures. Limit a single repair loop to three attempts before reporting a repeated failure or missing decision. Do not commit until the user confirms the change is fully complete and correct.
